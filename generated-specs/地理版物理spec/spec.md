### ⚠️ 核心设计理念

> **地理知识、参数探索、地图判读和反馈演示是同一个地理场景的四个状态，不是四个独立模块的拼接。**
>
> 每一个知识点对应一个可视化地理场景，这个场景贯穿「讲解→探索→答题→反馈演示」四个阶段。学生始终在同一个地图、剖面、气候图或地理过程动画里学习和作答：讲解时场景展示地理现象，探索时场景开放参数和图层，答题时场景锁定状态等待判读，反馈时场景直接演示正确过程和常见误区。
>
> **如果把地图、剖面、气候图、图层变化和动态反馈去掉，只剩文字和选择题，这个产品就没有存在的价值。**
>
> 技术选型：
> - **SVG**：地图边界、等高线、地形剖面、气候图、板块边界、河流流域、城市节点、图例和交互热区——矢量精确，支持 CSS 动画、标注和状态切换
> - **Canvas + JS**：风场、洋流、降水粒子、泥沙扩散、城市热力、地震波等连续动态过程——逐帧渲染，支持大量动态元素和实时参数响应
> - **CSS 动画**：UI 过渡、经纬网扫描、图层淡入、等高线流光、标题页粒子——提升界面沉浸感
>
> **禁止降级**：不可以用静态图片替代核心地理可视化，不可以用纯文字描述替代地图/图表判读，不可以跳过探索阶段的交互功能。

## 四、视觉风格规范

> 本节强制约束游戏的视觉表现。地理游戏的视觉目标是「专业地图册 + 动态地球科学工作台」：清晰、明亮、可判读，有空间感和图层感，地图、剖面、气候图和流场变化是视觉中心。

### 整体气质

**地理观测工作台感**：学生打开页面应该感觉站在一张可操作的地理观测台前，面前是地形沙盘、地图图层、剖面图、气候图、风场箭头和区域数据。不是课本截图，是「能动手判读」的互动地理场景。

### 背景系统

> 背景不是装饰，是氛围的基础。本项目使用全局固定背景图，所有 UI 和地理可视化浮在这张图之上。背景图必须由开发者在构建时编写提示词并调用生图模型生成。**禁止用 CSS 渐变、纯色或 SVG 冒充背景图。**

**背景图生成要求**：
- 提示词方向：**明亮专业地理地图册 / 地球科学工作台背景**——地形沙盘、分层地图、抽象气候图层、经纬网、地球科学展台，整体清晰、专业、无主体人物、无可读文字
- 参考关键词：`bright professional geography atlas workbench, layered topographic maps, terrain sandbox model, subtle GIS panels, contour lines, climate visualization panels, calm educational atmosphere, no people, no readable text, wide background composition`
- 如果无法调用生图模型，**必须停下来告知用户，不可用 CSS 替代**

**什么是"生图"**：
- ✅ 调用生图模型，输入提示词，获得一张真实的图像文件
- ❌ 用 CSS 渐变、box-shadow 画出来的图形 — 这不是生图
- ❌ 用 SVG path 手动描绘 — 这不是生图
- ❌ 用 Canvas 代码绘制 — 这不是生图

**实现要求**：
- `background-image` 固定铺满视口，`background-size: cover; background-position: center; background-attachment: fixed`
- 背景图上方叠加一层半透明中性灰遮罩，防止背景图案干扰前景内容的可读性。遮罩必须使用中性灰（`rgba(0,0,0,0.30)` 左右），不可使用带色调的色值，防止遮罩对前景文字色温产生干扰。地理版背景明亮，遮罩透明度可根据页面内容密度微调

> 原则：背景图是固定的氛围底图，所有动态效果和注意力焦点在前景的地图、剖面、图表、参数控件和反馈演示上。背景不应分散对核心内容的注意力。

### 标题页图层层级原则

> 背景图和遮罩必须永远位于所有 UI 内容之下，不得遮挡标题、按钮、地图缩略图、章节入口等任何前景元素。

- 推荐用 CSS `background-image` 属性实现背景图（作用于 body 或最外层容器），天然不会覆盖任何内容
- 如果用独立 div 实现背景图，必须确保该 div 不遮挡 UI——开发者自行选择最稳妥的实现方式
- 遮罩层同理，必须位于所有 UI 元素之下，背景图之上
- 粒子 Canvas 不拦截 UI 点击事件

### 标题页氛围粒子（必须实现）

> 标题页必须有与地理主题匹配的氛围粒子效果，强化沉浸感。

- **粒子类型**：经纬网扫描点、风场微粒、雨带粒子、等高线流光或卫星轨迹点
- 数量 10-30 个，随机分布在背景层，缓慢漂移、扫描或低速流动
- 粒子在标题页全程可见；进入章节后可保留低密度版本作为氛围层，或关闭（不强制）
- 用 Canvas 或 CSS animation 实现均可，不影响性能
- 尊重 `prefers-reduced-motion`（关闭粒子运动，保留静态低透明纹理）

### UI 元素风格

> 所有 UI 元素走「清晰地理工作台」路线：清楚、可扫读、专业，有地图册和观测仪器感，但不浮夸。

- 标题和按钮可以有经纬网切线、等高线纹理、地图扫描光、轻微描边或 `text-shadow`
- 面板以浅色地图纸、低透明灰白、岩灰、浅钢蓝、低饱和墨绿为主；夜间观测主题才使用深色半透明面板
- 章节卡片、题目面板、参数面板、图例面板必须视觉区分
- 卡片圆角 4-8px，保持仪器感，不要过度圆润
- 所有按钮必须有 hover、active、disabled 和 selected 状态
- 图例、单位、比例尺、方向提示和颜色编码必须清晰，不得为了风格模糊掉数据含义

### SVG/Canvas 可视化风格

> 地理可视化是本产品的核心，不是插图装饰。

**SVG 必须承担的内容**：

| 地理对象 | SVG 要求 |
|----------|----------|
| 分层设色地图 | 高程、温度、降水、人口密度、资源分布等以图层表达；每层有图例、单位和透明度控制 |
| 等高线与地形阴影 | 等高线密度随坡度变化；标高点清晰；山脊、谷地、鞍部、陡崖可识别 |
| 地形剖面 | 地表曲线、海拔标尺、岩层/植被/积雪/河谷剖面分层清楚 |
| 风场与洋流 | 箭头方向准确；线宽、颜色或粒子密度表达强度；流线可动 |
| 气候图 | 气温折线、降水柱状、月份刻度、气候类型标注、判读辅助线 |
| 板块构造图 | 板块边界、运动箭头、碰撞/张裂/俯冲剖面、火山地震带 |
| 水文过程图 | 河流流向、侵蚀岸/堆积岸、三角洲推进、洪泛区 |
| 人文地理图层 | 人口热力、城市节点、交通流线、资源区位、产业联系 |
| 题目热区 | 地图点选/框选的可交互区域，必须有 hover/selected 状态 |

**SVG 质量硬约束**：
- 每个知识点至少有一个 SVG 或 SVG + Canvas 混合核心可视化
- 同一知识点四阶段共用同一可视化，通过 `vis_state` 切换状态
- 所有 SVG 图层需要有语义化分组，例如 `base-map`、`terrain-layer`、`climate-layer`、`flow-layer`、`labels-layer`、`interaction-layer`、`feedback-layer`
- 关键地理变量必须有可解释的视觉编码：颜色、线宽、透明度、箭头长度、粒子密度、等值线密度、符号大小
- 地图图层必须有图例，图例说明颜色/符号/单位，不得只靠用户猜
- 标注必须有避让策略，不遮挡关键地物、图例、题目选区；必要时使用引线和锚点
- 动态标注平滑移动，不跳变
- 可交互对象必须有 hover、active、selected、locked、correct、incorrect 状态
- 地图、剖面、图表的比例和方向提示必须清楚；简化示意图也要标注“示意”或说明数据范围
- 手机端 SVG 必须可缩放、可平移或重排，核心标注不能被裁切

### 地理可视化原语速查

| 要画的东西 | 推荐技术 | 为什么 | 关键绘制点 |
|------------|----------|--------|------------|
| 分层设色底图 | SVG path + clipPath + linearGradient / discrete fill | 地理区域需要可点击、可标注、可按图层控制 | 区域边界清晰；主变量色带必须有图例；次要边界用低透明描边 |
| 等高线 | SVG path + stroke-dasharray + textPath | 线条精确，便于按海拔分组、hover 高亮和动画展开 | 等高线必须闭合或合理出图幅；坡陡处线距更密；每隔若干线标注海拔 |
| 地形阴影 | SVG filter + feGaussianBlur / feDropShadow + 半透明叠层 | 让地貌有体积感，又不破坏数据色 | 光源方向统一；山脊亮、谷地暗；阴影 opacity 低于主色带 |
| 地形剖面 | SVG path + area fill + 坐标轴 + clipPath | 剖面需要精确标尺、可叠加岩层/植被/雪线 | 地表曲线平滑；海拔轴和水平距离轴清楚；剖面层用 clipPath 限制范围 |
| 河流与流域 | SVG path + 渐变 stroke + marker 箭头 + Canvas 粒子 | 河流需要方向、支流层级和动态流动 | 上游线细、下游线粗；流向箭头顺坡；支流汇入点清楚 |
| 风场/洋流 | SVG path 流线 + marker + Canvas 粒子 | 大量流线可解释方向和强弱，粒子表达连续运动 | 箭头方向准确；线宽/粒子速度映射强度；寒暖流必须区分 |
| 降水/云带 | Canvas 粒子 + SVG 云带轮廓 / 等值线 | 粒子数量和密度可表达降水强度 | 粒子不遮挡标注；降水密度对应数值；云带边缘柔和 |
| 气候图 | SVG rect 柱状 + path 折线 + axis/grid | 气候判读依赖清晰坐标和月份刻度 | 降水柱和气温线分轴或明确单位；南北半球季节差异可标注 |
| 板块边界 | SVG path + pattern stroke + 运动箭头 | 边界类型需要符号化表达 | 碰撞、张裂、转换边界使用不同线型；箭头方向不能含混 |
| 人口/城市热力 | SVG symbol/use + radialGradient heat spots | 节点和热力可独立控制 | 城市节点大小映射等级；人口热力不得与温度热力混淆 |
| 题目热区 | SVG transparent path + data-id + focus ring | 地图点选/框选需要稳定命中区域 | 热区可比可见区域略大；hover 显示边界；选中态不覆盖原始数据色 |
| 参数面板/图例 | HTML/CSS + SVG swatch | DOM 更适合读数和控件 | 每个色带、线型、符号都有标签、单位和范围 |

#### 地理 SVG/CSS 质感配方

| 视觉对象 | 具体做法 |
|----------|----------|
| 分层设色地形 | 用离散色阶表达高度，叠加 5%-12% opacity 的地形阴影；山地边缘可用细浅色描边模拟受光面，低地保持低饱和，避免色块过艳 |
| 等高线 | 低海拔线用低透明细 stroke，高海拔线略深；主等高线每 4-5 条加粗；用 `stroke-linejoin: round` 避免折角生硬；标高文字沿 `textPath` 或贴近线段 |
| 山脊/谷地 | 山脊用极淡亮线沿 ridge path，谷地用低透明冷色阴影；两者必须跟随等高线结构，不得随意装饰 |
| 河流 | 主河道用双层 stroke：底层较宽低透明蓝色，顶层较窄亮蓝；用 `stroke-linecap: round`；可沿 path 移动小粒子表达流向 |
| 湖泊/海域 | 使用蓝色径向或线性渐变，岸线有细亮边；深水区更深，浅岸区更浅；水域纹理 opacity 很低 |
| 风场箭头 | 箭杆用 `path`，箭头用 `marker` 或 polygon；箭头长度/线宽映射风速；低风速可用虚线或低透明 |
| 洋流 | 暖流用橙红线 + 柔和外发光，寒流用钴蓝线 + 低透明冷光；线上粒子沿流向移动；交汇处不要让颜色混成脏色 |
| 雨带/降水 | SVG 绘制云带轮廓，Canvas 绘制雨粒；降水强度用粒子密度和下落速度表达，不能只改颜色 |
| 气候图 | 坐标轴和网格用低透明灰线；降水柱圆角 2-3px；气温折线用高对比 stroke，数据点小圆点可 hover 显示值 |
| 地形剖面 | 地表曲线下方用分层填充；岩层可用 `pattern` 斜纹/点纹；积雪用白色薄层；植被用低矮绿色短线或点状纹理 |
| 板块边界 | 俯冲边界用齿状三角 marker，张裂边界用双向箭头和裂隙虚线，转换边界用平行反向箭头；符号必须进入图例 |
| 城市/人口 | 城市节点用圆点 + 外环，等级越高外环越大；人口密度用半透明热力斑点，不得盖住地名 |

#### 地理动效模式

- **等高线展开**：章节过渡或讲解起始时，等高线可用 `stroke-dasharray` / `stroke-dashoffset` 由低海拔到高海拔依次绘出，帮助用户理解地形起伏。
- **地形抬升**：板块碰撞或山地形成时，剖面曲线通过 path 插值逐步隆起，阴影和等高线同步更新，不能只让山体整体上移。
- **雨带推进**：季风或锋面讲解中，云带轮廓平移，降水粒子密度随地形迎风坡增强，背风坡粒子减少。
- **河流侵蚀/沉积**：弯道外侧用短暂高亮和细粒子表示侵蚀，内侧用沉积色块逐渐累积；反馈阶段可对比错误预测和真实变化。
- **洋流流动**：粒子沿曲线运动，速度映射洋流强度；寒暖流交汇时粒子不应乱跳，交汇区可用低透明涡旋。
- **风向旋转**：风向旋钮改变时，箭头和粒子方向连续旋转，不得瞬间翻转。
- **城市扩张**：热力或土地利用斑块从城市节点向外扩散，受交通线和地形约束；不能均匀圆形扩散。
- **参数变化**：温度、降水、海拔、人口等连续变量必须插值过渡，图例读数同步平滑变化。

#### 地理标注与图例原则

- 地名、地貌名、气候类型、数值读数必须贴近目标元素，并用细引线和小锚点连接。
- 标注不得覆盖河流汇合点、山脊线、风场箭头、气候图峰值等判读关键位置。
- 多标注冲突时，优先保留题目相关标注，次要标注折叠为可 hover 展开。
- 图例必须解释颜色、线宽、箭头、透明度、符号大小、粒子密度、纹理含义。
- 数值和单位使用等宽字体，单位紧跟数值，例如 `1200 m`、`25 °C`、`800 mm`。
- 答题阶段可以隐藏部分答案性标注，但不能隐藏完成判读所需的坐标轴、比例、方向、单位和图例。

#### 地理交互态视觉暗示

| 状态 | 视觉表现 |
|------|----------|
| hover 地图区域 | 区域边界加亮，填充增加 5%-10% 透明亮层，显示名称 tooltip；不得覆盖原始色带 |
| hover 流线/箭头 | 线条略加粗，沿线出现短暂方向粒子，tooltip 显示变量名和单位 |
| dragging 剖面线/参数点 | 显示虚线辅助线、当前坐标/数值读数，相关剖面或图层实时更新 |
| selected 区域 | 使用外描边、角标或半透明斜纹表示，不直接把区域涂成反馈色 |
| locked 答题态 | 非题目相关控件降 opacity，核心图层保留；cursor 改为 default |
| correct | 反馈层短时绿色描边/路径高亮，并播放正确过程动画 |
| incorrect | 先用温和红色短时标出错误选择，再回到原图层色彩并演示正确路径 |
| disabled | 控件和图层开关降饱和，保留可读标签，不误导为未加载 |

#### 地理常见画错点

- 河流不得逆坡流；流向箭头必须符合地形或图中说明。
- 等高线不得随意相交；同一条等高线不能标注多个不同海拔。
- 山脊、山谷、鞍部、陡崖的等高线形态必须能被判读，不能只是随机波纹。
- 气候图不能省略坐标轴、月份、单位；气温线和降水柱不能共用未说明的比例。
- 温度热力、人口热力、灾害风险不能全部用同一种红橙色编码。
- 风场箭头、洋流线、交通流线不得穿过图例和题干关键文字。
- 板块边界类型必须用不同符号表达，不能只用一条普通线。
- 简化地图必须标注“示意”或说明数据范围，不能让示意图冒充精确地图。
- Canvas 粒子不得遮挡地名、坐标轴、题目热区和关键图例。
- 答题反馈不能永久改写地图原始色带，否则会破坏后续判读。

#### Canvas 适用范围

Canvas 用于大量粒子或连续场变化：

- 降水粒子、雪线变化、云团移动。
- 河流泥沙扩散、河道摆动、三角洲推进。
- 风沙移动、沙丘迁移、火山灰扩散。
- 洋流粒子、海温扩散、上升流动态。
- 地震波、城市扩张热力渐变、人口流动。
- 大量风场/流场粒子的逐帧动画。

SVG 与 Canvas 可以混用：SVG 负责精确地图、剖面、标注、坐标、图例和交互热区；Canvas 负责连续粒子、流场、扩散和动态氛围。

### 配色方案

> 配色必须先服务地理编码，其次才服务氛围。颜色不能只是好看，必须能被图例解释。

**UI 基础色**：
- 背景/表面：雾白、浅灰地图纸、暖白、岩灰、浅钢蓝、低饱和墨绿
- 面板分隔：低透明冷灰、纸面灰、低饱和青灰、岩灰
- 文字/标注：深墨绿、炭灰、地图黑、冷白、浅暖白
- 交互强调：青蓝、琥珀、雷达绿、珊瑚红、地图黄、植被绿、海洋蓝
- 正确/错误：清晰绿色 / 温和红色，仅用于反馈层，不永久改变原图层色彩

**地理专题色板**：
- 地形高程：深海蓝 → 海岸青 → 低地绿 → 丘陵黄绿 → 高原赭黄 → 山地棕 → 雪线白
- 气温热量：冰蓝 → 青绿 → 温带绿 → 暖黄 → 橙 → 深红
- 降水湿度：雾白 → 浅蓝 → 天蓝 → 深蓝 → 蓝紫
- 洋流/海温：暖流橙红、寒流钴蓝、上升流青绿
- 板块/灾害：板块紫、断层玫红、火山橙红、地震亮红、滑坡土褐
- 人口/城市：人口紫红、城市琥珀、交通亮橙、资源金黄、产业蓝紫

### 排版规范

- 标题字体要有地理主题感，但不能牺牲可读性

- 地图标注、图例、单位、题干必须清晰，正文最小字号不低于 14px
- 数值和单位建议使用等宽字体，例如 `1200 m`、`25 °C`、`800 mm`

- 移动端参数面板可折叠，但不得遮挡地图关键标注

### 动效标准

- **标题页进场**：背景图淡入 → 经纬网/等高线粒子开始 → 主标题上浮淡入 → 副标题淡入 → 按钮淡入，依次触发，总时长 ≤ 1.5s
- **标题页按钮**：常态有轻微呼吸脉动，hover 轻微上浮或描边发亮，click 短暂按压
- **标题页 → 章节主页**：地图扫描线或等高线光带扫过，内容淡出淡入，不瞬切（500-800ms）
- **章节过渡**：1.5-3s，可使用地图扫描、地形抬升、等高线展开、卫星轨迹扫过
- **参数变化**：温度、降水、海拔、人口等连续变量必须插值过渡，图例读数同步平滑变化
- **反馈演示**：先呈现用户选择的结果，再演示正确路径，过程要可暂停或重播
- 动效必须服务理解、反馈或氛围，不允许无意义闪烁
- `prefers-reduced-motion` 下关闭装饰性动画，保留核心地理过程演示的必要版本

## 七、信息结构

### 导航结构

```text
标题页
├── 开始学习 → 章节主页
└── 继续学习 → 章节主页（恢复存档进度，仅有存档时显示）

章节主页（核心导航枢纽，每次完成章节后返回这里）
├── 章节列表（纵向或横向排列）
│   ├── 已完成章节 → 亮色 + 完成标记 + 可点击回看
│   ├── 当前可进入章节 → 高亮 + 引导动效 + 可点击进入
│   └── 未解锁章节 → 灰色/锁定 + 不可点击
└── 整体进度展示（如 2/6 章已完成）

学习中（线性推进，章内不可跳转）
├── 章节过渡屏
├── 知识点闭环（重复 3-4 次/章）
│   ├── 讲解阶段（地图/图表动画 + 文字）
│   ├── 探索阶段（交互式地图/剖面/气候图）
│   ├── 答题阶段（地理判读题）
│   └── 反馈演示（同场景动画演示答案）
└── 章末总结（知识卡片 + 成就展示）→ 返回章节主页

结局总结页（全部章节完成后触发）
├── 成就墙（所有已解锁成就）
├── 各章回顾
└── 返回章节主页
```

> 本游戏为线性解锁路径——必须通过第 N 章才能解锁第 N+1 章。但章节主页允许回看已完成章节。

### 游戏界面布局

| 界面 | 核心内容 | 交互方式 |
|------|---------|---------|
| 标题页 | 游戏名称（主题化字体特效）+ 副标题 + AI 生成地理背景图（中性遮罩）+ 开始/继续按钮 + 氛围粒子 | 点击按钮 |
| 章节主页 | 章节列表（已完成/当前/未解锁状态区分）+ 整体进度 | 点击章节进入 |
| 章节过渡 | 章标题 + 本章核心变量/图层预告 + 地图扫描或地形动效 | 点击"进入" |
| 讲解阶段 | 上方：SVG/Canvas 地理可视化区域（动画播放）；下方：讲解文字（逐段显现）+ 继续按钮 | 点击继续 |
| 探索阶段 | 中央：交互式地图/剖面/气候图（带拖拽/滑块/图层开关）；下方：参数面板 + 引导文字 + "来挑战"按钮 | 拖拽/滑动/切换 + 点击 |
| 答题阶段 | 上方：可视化（锁定特定状态）；下方：题目文字 + 选项/点选/框选/拖拽区 | 点击、点选、框选、拖拽 |
| 反馈演示 | 上方：可视化（播放答案演示）；下方：反馈文字 + 继续/重试按钮 | 点击继续或重试 |
| 章末总结 | 变量卡片 + 图像判读方法 + 常见误区 + 本章成就展示 | 点击继续 |
| 结局总结 | 成就墙（卡片网格）+ 各章一句话回顾 + 重新开始按钮 | 点击"重新开始" |

### 标题页设计规范

**字体层级**：
- 主标题字号 ≥ 40px（移动端）/ ≥ 56px（桌面端），有地理主题字体特效（等高线纹理、经纬网切线、地图扫描光、轻微描边或亮色填充）。标题基色必须可见，特效是增强而非前提
- 副标题字号约为主标题的 40-50%，字重轻，颜色比主标题略弱，体现层次
- 按钮文字简洁有力，建议使用"开始学习"、"继续学习"

**进场动画**（页面加载时依次触发）：
1. 背景图淡入（300ms）
2. 经纬网/等高线粒子开始漂浮或扫描
3. 主标题上浮淡入（500ms，delay 200ms）
4. 副标题淡入（400ms，delay 600ms）
5. 按钮上浮淡入（400ms，delay 900ms）

**按钮动效**：
- 常态：轻微呼吸脉动或细描边亮度变化（周期 3s）
- hover：描边发亮 + 轻微放大或上浮
- click：短暂按压（scale 0.97）

**标题页 → 章节主页过渡**：点击按钮后，标题页内容淡出，可加地图扫描线、等高线光带或经纬网汇聚效果（500-800ms），背景图保持不动

## 九、交互设计

### 交互模式选择

**本项目选择**：新手友好 + 地理探索式

**选择原因**：目标用户是学生，基本操作（点击推进 + 选择答案）要极简，但探索阶段需要滑块、图层开关、地图点选、剖面拖拽、时间轴等交互来建立地理空间感和因果直觉。

### 操作映射

| 操作 | 实现方案 | 说明 |
|------|---------|------|
| 推进讲解 | 点击"继续"按钮 | 文字和地理动画同步，按钮在动画播完后出现 |
| 交互探索 | 拖拽地图点/剖面线/调节滑块/切换图层 | 可视化实时响应，数值面板同步更新 |
| 回答问题 | 点击选项、点选区域、框选范围、拖拽标注或排序 | 提交后进入反馈演示，答错可重试 |
| 观看反馈 | 自动播放 + 点击继续 | 反馈动画播完后出现继续按钮 |
| 存档 | 自动 | 每次状态变化自动写入 localStorage |
| 读档 | 点击标题页"继续学习" | 进入章节主页，恢复存档进度 |

### 交互探索的具体模式

> 探索阶段的交互方式取决于地理内容，以下为常见模式：

| 交互模式 | 适用场景 | 操作方式 |
|---------|---------|---------|
| 滑块调参 | 纬度、海拔、降水、温度、坡度、流速、人口密度等连续变量 | 拖拽滑块，地图/剖面/图表实时更新 |
| 方向旋钮 | 风向、洋流方向、板块运动方向 | 拖拽旋钮改变方向，箭头和粒子连续旋转 |
| 图层开关 | 地形、气候、水文、人口、交通、资源等图层 | 点击 toggle 或标签页显示/隐藏图层 |
| 地图点选 | 区域定位、地貌识别、城市/河流/山脉选择 | 点击 SVG 热区，显示选中态 |
| 地图框选 | 流域范围、气候区、人口密集区、灾害风险区 | 拖出矩形或套索，计算范围重叠 |
| 剖面排序 | 地貌演化、河流侵蚀阶段、垂直自然带 | 拖拽阶段卡片排序 |
| 参数预测 | 先预测变量变化结果，再播放模拟 | 选择预测结果，播放后对比 |
| 播放/暂停 | 地理过程模拟 | 点击播放按钮，可暂停在任意时刻观察 |

### 交互反馈

| 操作 | 视觉反馈 | 状态变化 |
|------|---------|---------|
| 阅读讲解 | 文字显现 + 地理动画播放 | 进入探索阶段 |
| 拖拽参数 | 可视化实时变化 + 数值更新 | 无状态变化 |
| 切换图层 | 图层淡入/淡出，图例同步更新 | 无状态变化 |
| 答对 | 正确图层高亮，关键过程播放，成功色反馈 | 可能触发成就 |
| 答错 | 错误路径短暂演示，再切回正确过程；文案温和 | 记录错误，不扣分 |
| 探索中特殊操作 | 可能触发创意成就的 toast | 解锁隐藏成就 |
| 进入新章 | 章节过渡动画 | currentChapter +1 |
| 通关 | 跳转结局成就墙 | finished = true |

## 十、核心机制约束

> 以下是**不可更改的规则**，开发时必须遵守。

### 地理准确性（极其重要）

- 地名、区域事实、空间关系必须正确——**这是本产品的底线**
- 气候类型、气温降水规律、季风、洋流、地形雨、雨影效应等因果必须正确
- 地貌成因、板块运动、流水侵蚀沉积、风化风蚀、冰川地貌等过程必须正确
- 人口、城市、资源、交通、产业布局等人文地理判断不能使用过度简化或错误因果
- 图表单位、比例、方向、图例必须一致
- 探索阶段的参数范围必须地理上合理
- 题目的正确答案必须经过验证

### 知识自检规则

> **AI 在生成内容时，必须对所有涉及的地理知识执行自检。** 这是强制流程，不可跳过。

自检清单（每个章节输出后逐条核对）：
1. **事实验证**：本章出现的地名、区域特征、真实案例是否正确？
2. **因果验证**：气候、地貌、水文、人文地理过程是否符合地理规律？
3. **图表验证**：地图、剖面、气候图、流线图是否有单位、方向、比例、图例？
4. **参数验证**：探索阶段的参数范围是否合理？变化方向是否符合规律？
5. **可视化一致性**：可视化中的变化是否与地理机制一致？例如海拔升高温度降低、迎风坡降水增强、寒流降温减湿
6. **选项设计**：错误选项是否对应真实学生常见误区，而不是随机干扰？

> 如果自检发现错误，必须修正后再输出。在输出末尾附上自检结果摘要。

### 知识点四阶段闭环规则

> **这是本游戏区别于普通题库的核心机制。** 每个知识点必须走完四个阶段，且四个阶段共用同一个地理可视化。

**阶段 1：讲解**
- 一边说原理一边播放地图/剖面/图表动画，学生看到地理现象
- 可以分多段讲解（1-3 段），每段 60-120 字，每段对应不同的 `vis_state`
- 通俗易懂，先给空间直觉再给概念和规律
- 关键术语首次出现时加粗并解释
- 动画和文字同步：文字说到迎风坡，动画就展示气流抬升和降水增强

**阶段 2：探索**
- 开放交互参数，学生自己拖拽/调节/切换图层
- 提供引导文字，例如"试试把海拔升高，观察气温和植被带如何变化"
- 探索没有对错，纯粹建立直觉
- 可视化实时响应参数变化，数值面板和图例同步更新
- 某些特殊操作可触发创意成就

**阶段 3：答题**
- **题目必须基于前两个阶段的可视化出题**，考察学生对地图、图表和地理过程的理解
- 可视化锁定在特定状态，或隐藏部分答案性标注
- 题型可以是 3 选 1、地图点选、框选、拖拽标注、图层匹配、气候图判读、剖面排序、参数预测
- 正确答案必须唯一或按题型规则明确

**阶段 4：反馈演示**
- **不管答对还是答错，都用同一可视化演示**
- 答对：播放正确过程 + 高亮关键变化 + 肯定 + 为什么对（30-80 字）
- 答错：先演示「你选的会怎样」再演示「正确的是怎样」+ 不批评 + 指出错在哪（50-100 字）
- 答错可以重试（但不重复触发成就）
- 语气鼓励："没关系，我们看看地图和图层会怎样变化" 而不是 "错了"

### 四阶段的可视化一致性

- **禁止**每个阶段造一个不相关的图——四个阶段是同一个地图/剖面/图表场景的不同状态
- 讲解时：可视化处于「演示模式」，按预设流程播放
- 探索时：可视化处于「交互模式」，参数和图层开放
- 答题时：可视化处于「锁定模式」，特定参数固定或部分标注隐藏
- 反馈时：可视化处于「演示模式」，播放答案对应的过程

### 成就系统规则

> **本游戏不使用分数制。** 用成就替代评分，每章 3 个成就，成就要有个性和记忆点。

**每章 3 个成就**：

| 类型 | 触发条件 | 地理风格 |
|------|----------|----------|
| 全对成就 | 本章所有题首次答对 | 制图师 / 观测员 / 判读专家风格 |
| 全错成就 | 本章所有题首次答错 | 轻微调侃但不伤人 |
| 创意成就 | 探索阶段触发特殊但合理参数组合 | 奖励好奇心 |

规则：
- 成就名 6 字以内优先，描述 30-50 字
- 全对/全错基于首次作答
- 重试不重复触发成就
- 创意成就由地理内容决定，例如把降水、坡度和植被参数组合到极端但合理状态，触发侵蚀风险提示
- 不显示分数、百分比或等级

### 章末知识总结

每章结束后展示：
- 本章核心变量
- 图像判读方法
- 关键地理因果链
- 常见误区
- 本章成就

### 结局总结

全部章节完成后进入结局总结：
- 成就墙
- 各章一句话回顾
- 关键地图/图表回顾
- 重新开始按钮

### 地理场景速查

#### 地形与地貌
- 等高线判读：山峰、山谷、山脊、鞍部、陡崖
- 河流侵蚀：上游下切、中游侧蚀、下游堆积
- 三角洲演化：泥沙输入、海浪侵蚀、沉积推进
- 风成地貌：风向、沙源、植被覆盖影响沙丘形态

#### 气候与大气
- 纬度与太阳高度：纬度变化影响热量分布
- 海陆热力差异：季风环流、昼夜海陆风
- 地形雨：迎风坡抬升降水，背风坡雨影
- 洋流影响：暖流增温增湿，寒流降温减湿
- 气候图判读：最冷月/最热月、降水季节分配、南北半球

#### 水文与海洋
- 流域与分水岭：流向、支流、汇水区
- 河流补给：雨水、冰雪融水、湖泊/地下水补给
- 洪水过程：降水强度、坡度、植被、城市化
- 洋流系统：寒暖流、上升流、渔场形成

#### 板块与灾害
- 板块碰撞：褶皱山脉、地震带、火山弧
- 板块张裂：裂谷、海岭、新洋壳
- 俯冲带：海沟、火山岛弧、深源地震
- 灾害风险：地震烈度、滑坡、泥石流、洪涝风险

#### 人文地理
- 人口分布：自然条件、交通、经济机会
- 城市化：城市扩张、热岛效应、土地利用变化
- 工业区位：资源、交通、市场、劳动力
- 交通流线：节点、通道、可达性
- 区域综合：自然条件与人类活动叠加

### 关键地理规律与知识点

- 海拔升高通常气温降低，但具体递减率需按内容文件或教学设定说明

- 河流从上游到下游，侵蚀、搬运、沉积作用重点不同
- 人口、城市、产业布局受自然条件、交通、资源、市场和政策等多因素影响

## 十二、技术约束

| 维度 | 约束 |
|------|------|
| 技术栈 | 单文件 HTML + CSS + JavaScript + 内嵌 SVG/Canvas |
| 部署方式 | 静态文件，可直接打开 |
| 外部依赖 | 默认零依赖；如使用字体 CDN 必须有 fallback |
| 进度缓存 | localStorage |
| 性能 | 首屏 UI < 2s；核心动画 ≥ 30fps；SVG 操作不卡顿 |
| 响应式 | 桌面、平板、手机可用；移动端核心可视化可缩放 |
| 无障碍 | 键盘可操作主要按钮；颜色编码配合文字/图例；减少动画模式可用 |

### SVG 性能约束

- 复杂地图图层应合理简化路径，避免单个 SVG 节点过多导致卡顿。
- 大量粒子使用 Canvas，不用数百个 SVG circle 硬撑。
- 图层开关应改变 group 可见性，避免销毁重建。
- 移动端可降低非核心粒子密度，但不得删除核心地理信息。
- 参数变化时优先更新必要 path、transform、opacity、stroke、fill 或 Canvas 粒子状态，不得每次重建整棵可视化 DOM。

## 十三、开发指引

收到本 spec.md 后：
1. 进入 plan 模式，按章节拆分开发任务
2. 每个任务读取对应的 SKILL 文件，提取具体地理知识、区域事实、图表数据、参数范围和题目依据
3. 为背景图编写地理主题提示词并调用生图模型生成；如无法生图必须停下来告知用户，不可用 CSS 替代
4. 实现标题页（AI 背景图 + 中性遮罩 + 进场动画 + 粒子 + 地理主题字体 + 按钮动效）
5. 实现全局 UI 框架（地图纸面板 / 图例 / 参数控件 / 清晰按钮 / 响应式布局）
6. 实现章节主页（所有章节解锁状态、当前章节高亮、已完成可回看、未解锁锁定）
7. 逐章实现知识点的四阶段闭环（讲解→探索→答题→反馈），每个知识点一个地理可视化
8. 实现成就系统（每章 3 个成就：全对/全错/创意）
9. 遵守「核心机制约束」中的所有规则
10. 执行「知识自检」——逐章核对地理事实、因果、图表、单位和答案的正确性
11. 对 SVG/CSS 绘制指南执行专项自检，确认地理可视化原语、质感配方、动效模式、标注/图例、交互态、常见画错点均已落实
12. 完成后执行全量自检（对照验收标准）
