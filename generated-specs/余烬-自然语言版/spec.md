## 【用户需求描述】 ← 唯一的填空,整份 spec 的方向盘

我想做一个**关于"守住一点光"的生存游戏**。你是黑暗里一颗快要熄灭的余烬——一个会呼吸、会往外蹦火星的小光点。四周是浓得化不开的黑。

核心感觉是**孤独但好看,紧张但温柔**。不是打打杀杀,是"别灭"。光是你唯一的依靠:**光圈照到的地方你才看得见,黑暗也只敢待在光照不到的地方**。可余烬在持续变冷,光会一点点暗下去;一暗,光圈就缩小,黑暗就逼近。

我要一个**两难**:光既是安全,也是诱饵。**你越亮,黑暗里越多火种被你召唤出来(可以吸收、续命),但黑暗也被你惊动得越凶,你自己也烧得越快**。所以玩家得一直拿捏:要亮一点多捞火种、把黑暗推远,还是收着点别把黑暗惹毛、别太快烧干。这个"亮一点还是省着点"的拉扯,就是整个游戏。

没有通关,这是一场**熬**:活得越久越好。而且我想奖励"敢亮的人"——分数该跟你一路保持的亮度有关,不是龟缩到底就能高分。死亡就是熄灭:余烬炸成一片火星,然后一切归黑。

要能用鼠标 / 手指玩(余烬跟着指尖飘),一局几分钟。这次它是个**街机生存游戏,不是睡前读物**,所以"死了再来一把"的欲望是好的、该鼓励的。

视觉全部用 SVG / CSS / Canvas 粒子做,**不要任何图片**:发光的余烬、飘浮的火星、边缘蠕动的黑暗、星星点点的火种。要那种"暖光在黑里跳动"的质感。

> 下面所有内容,都是对这段描述的扩展与设计。

## 这是什么

余烬是一个**单局几分钟的街机生存游戏**,核心是一道**光的经济学**:光是你的命,也是你的麻烦。玩家全程只做一件事——在黑暗里移动着捞火种,把那点光续下去——但"该多亮"这个判断每一秒都在变。它要的不是反应快,是**拿捏**:贪亮会烧干、会招黑暗,过省会看不见、会被黑暗贴脸。成功的样子很具体:玩家死了会"啧"一声,然后立刻想再来一把,并且开始琢磨"这次该亮一点还是稳一点"。

## 怎么玩(核心循环与机制)

**核心循环(一句话)**:跟着指尖移动 → 在黑暗里捞到火种、补光 → 光在持续变冷、黑暗在持续逼近 → 不停权衡"该多亮" → 直到余烬熄灭,结算这一局熬了多久、有多亮。

这套玩法立在**三条互相咬合的曲线**上,这是从需求描述里"两难"长出来的核心设计,缺一条游戏就塌:

- **光量(brightness)= 唯一资源**。它同时决定三件事:① 光圈半径(你能看见多远、黑暗被推多远);② 余烬核心的存活(归零 = 熄灭 = 结束);③ 你的得分速率。光量**随时间持续衰减**,且**越亮衰减越快**(旺火烧得快)——所以高光是借来的、要还的。
- **火种(motes)= 唯一补给**。黑暗里随机浮现的小光点,余烬靠近即吸收、回补光量。**刷新速率随当前光量上升**:越亮,黑暗里被"召唤"出来的火种越多越近——亮是有回报的。
- **黑暗(the dark)= 唯一威胁**。从光圈外缘向内挤压的蠕动边界。**压迫强度随光量上升、也随存活时间上升**(越亮越惊动它,局势越久它越狠)。黑暗触到余烬核心 = 受伤(削一截光量);把光量压到 0 = 熄灭。

这三条曲线一咬合,**最优亮度就成了一个动态移动的甜点**:低光时火种少、衰减慢,但光圈小、看不清、黑暗贴脸;高光时火种多、光圈大、安全舒服,但烧得快、黑暗凶。随存活时间推移,黑暗整体变猛,逼着玩家不断重新校准"现在该多亮"。简单三条规则,逼出持续的判断——这就是这个游戏的深度来源,不靠堆机制。

**增强机制(有更好,没有也能玩)**:
- **过载冲(overdrive)**:短按可一次性烧掉一截光量,瞬间把光圈炸大、把附近黑暗猛推开、并吸光一片火种。救命用,但代价是之后更暗。给高手一个主动操作的出口。
- **阶段升级**:每熬过一个时间里程碑(如 30s / 60s / 90s),黑暗进入更凶的一档,同时整屏配色/粒子密度变化,给"熬下去"一个可感知的视觉奖励。

**胜负与进度**:没有通关,只有存活。**得分 = 全程对"当前光量"的时间积分**(∫ 亮度 dt)——熬得久且敢保持亮,分才高;龟缩到底只能拿低分。死亡 = 熄灭:余烬炸成一大片火星、屏幕过曝一下再缓缓沉入全黑,然后给明确的结算 UI(本局时长、得分、历史最佳)。

## 操控与手感

- **操控**:指针(鼠标 / 手指)为主——余烬**带缓动地朝指针飘**(不是硬贴,要有质量感、有拖尾);方向键 / WASD 作为备选。过载冲 = 点击 / 空格。移动端可单指拖。
- **核心动词**:飘移、捞(吸收火种)、躲(避开逼近的黑暗)、冲(过载)。
- **反馈即时**:每个动作都要有手感——吸收火种时核心"咽"一下亮一截 + 飘字(光量 +)+ 一小簇火星迸出;被黑暗碰到时暖红闪一下 + 核心抖 + 火星溅射;过载冲时一圈冲击波把黑暗和火种一起推开。**没有反馈的操作等于没生效。**

## 长什么样(视觉与气质)

> 视觉 / UI / 粒子的质量基线沿用 `spec_通用游戏.md` 的标准(主题化标题、主题化 UI、必做视觉反馈、动效缓动、`prefers-reduced-motion`),不在此复述。下面只写本作特有的视觉设计。

整体气质:**暗底、暖光、少即是多**。一种"在浓黑里护着一小簇火"的极简发光风——大量黑、一点跳动的暖橙金、危险时一抹深红。靠**光本身**做美术,不靠贴图。

**配色**:

| 用途 | 方向 | 说明 |
|------|------|------|
| 主色(底 / 黑暗) | 近黑的炭蓝,如 `#0a0b10` | 浓得化不开,衬出光 |
| 强调色(余烬 / 光) | 暖橙金,如 `#ffb347 → #ff7a18` 渐变 | 玩家核心与光圈,会随光量明暗 |
| 火种 | 偏白的暖黄微光 | 比余烬冷一点、亮一点,易辨认 |
| 危险 / 受伤 | 深红,如 `#e23b3b` | 只在被黑暗碰到时短暂出现 |
| 文字 / HUD | 暖白低亮 | 不抢光,贴合火的语义 |

**必须做出来的视觉效果(juice)**:

| 事件 | 视觉要求 |
|------|----------|
| 吸收火种 | 核心亮一截 + 飘字(光量+)+ 小簇火星迸出 |
| 被黑暗碰到 | 暖红短闪 + 核心抖动 + 火星溅射(暖红闪,不用刺眼纯红,贴火主题) |
| 光量偏低告急 | 光圈边缘开始不稳/抖动,核心心跳般急促脉动,提示"快灭了" |
| 过载冲 | 一圈可见冲击波推开黑暗与火种 + 短暂过曝 |
| 阶段升级 | 整屏配色/黑暗密度切换 + 一次低频脉冲,无瞬切 |
| 熄灭(Game Over) | 余烬炸成满屏火星 → 过曝 → 缓缓沉入全黑 → 结算 UI 淡入 |

**动效**:余烬移动必须缓动(有质量、有拖尾),不能匀速直线;一切切换淡入淡出,不瞬切;按钮 hover/active 要有光感反馈;目标帧率 ≥ 60fps(大量粒子用 Canvas,别用上百 DOM 节点硬跑);`prefers-reduced-motion` 下关闭背景漂浮装饰与屏幕抖动,**保留**核心的光圈明暗、火种与黑暗的低频运动(它们是机制,不是装饰)。

## UI 与氛围(标题 / HUD / 粒子 / SVG-CSS)

- **标题页**:大字"余烬"不能是普通 `<h1>`——暖金渐变(`background-clip: text`)+ 多层 `text-shadow` 发光 + 极轻的呼吸缩放入场;标题旁一颗真的在脉动、往上飘火星的余烬;底部一行轻提示"拨动余烬,别让它灭";有历史最佳时显示"上次熬了 {time}"。整页用**灰烬 / 火星上浮**粒子(库内效果:CSS/Canvas 上浮 + opacity 渐隐,10–30 颗,`pointer-events: none`)。
- **HUD(极简、叙事化)**:不要把数据堆屏幕角。**光量做成围绕余烬的一圈光环**(SVG `circle` + `stroke-dasharray`,随光量增减、低光时变红闪烁),而不是角落一根血条;存活时间用暖白低亮等宽数字,轻浮在上方;过载冷却用核心周围一道短弧表示。
- **SVG / CSS 技巧(本作怎么画)**:
  - 余烬核心 = 多层 `radial-gradient` 叠加的发光球 + 多层 `box-shadow` 做光晕,CSS 脉动;持续发射的火星用 **Canvas 粒子**(数量大,SVG/DOM 扛不住)。
  - 光圈 = 一个 `radial-gradient` 遮罩,中心透亮、边缘速暗,圈外近黑;光量变化时连续插值半径,**不瞬变**。
  - 黑暗边界 = 光圈外缘蠕动的暗色 Canvas/SVG 形,用噪声驱动起伏,**靠近光圈处被"推"回去**(受光量影响),不是一条死边。
  - 火种 = 小光点,星星闪烁 / 萤火虫式轻飘 + twinkle(SVG/CSS 即可)。
  - 状态反馈遵循:hover/active 结合光晕 + 缩放 + 位移,不只变色。

> 判断说明:本作核心视觉是**氛围与动作手感**(发光、粒子、蠕动黑暗),属于 `specforge/modules/ui-particles-svg.md` 的范畴,**不触发** `svg-css-visual-primitives.md`(那是给图表 / 地图 / 机制图 / 参数模拟这类**要标注、图例、单位、数据正确性**的可视化用的)。余烬没有要"画准"的数据,只有要"做出手感"的光——所以视觉鉴收看质感与反馈,不看数据编码。

## 图片(资产契约)

本产品**不需要任何真实位图资产**。核心视觉全部由 SVG / Canvas / CSS + 粒子实现,这是刻意的美术选择,不是降级。因此:不调用生图、无 `IMAGE_ASSET_MANIFEST`、无首启缓存流程。**但不得用"待生图占位"或任何方式假装这里本该有图**——这里本来就不该有图。

## 数据与状态

- **持久化(localStorage,只存轻量)**:历史最佳存活时长、最高分、设置(如 reduced-motion 覆盖、操控偏好)。每局结束写入。
- **运行时(不持久)**:当前光量、余烬坐标与速度、火种 / 黑暗 / 粒子状态、存活计时、当前阶段、过载冷却——都活在内存与游戏循环里,刷新即新开一局。
- 不存图片、不存 base64、不存大字符串。

## 技术约束

- 纯前端**单文件**(HTML + CSS + JS + 内嵌 SVG / Canvas),静态打开即玩,离线可用,零依赖(字体可 CDN 带 fallback)。
- 大量粒子与黑暗用 **Canvas**(目标 ≥ 60fps,移动端不卡);UI、HUD、标题、结算用 **HTML/CSS/SVG**;游戏循环用 `requestAnimationFrame`,逻辑用固定步长、渲染插值。
- 仅现代浏览器;首屏 < 2s。

## 护栏与验收(coverage checklist —— 下限保护)

这张清单既是**覆盖保证**也是**验收口径**;过不了就算没写完。它替代旧模板用十几章强制的"别漏项"。

- [ ] **核心循环可玩、不死局**:从标题进游戏,全程无需改代码即可正常游玩到熄灭、看到结算并能再开一局。
- [ ] **三条曲线都在且互相咬合**:光量衰减(越亮越快)、火种供给(随光量升)、黑暗压迫(随光量与时间升)——任意一条缺失或不联动,判未达成。
- [ ] **两难成立**:存在"贪亮会烧干/招黑暗、过省会看不清/被贴脸"的真实拉扯,最优亮度随时间移动,不是一个固定打法躺赢。
- [ ] **得分忠于需求描述**:分数与全程亮度相关(敢亮得分高),龟缩拿不到高分;无"通关"概念,是存活计分。
- [ ] **手感反馈齐**:捞火种、受伤、告急、过载、阶段升级、熄灭都有即时且主题化的视觉反馈(对照上方 juice 表)。
- [ ] **视觉无图实现**:余烬 / 光圈 / 黑暗 / 火种 / 粒子全部 SVG/Canvas/CSS;**没有任何图片,也没有假装该有图的占位**。
- [ ] **UI 主题化**:标题非普通 h1;HUD 叙事化(光环而非角落血条);按钮等无浏览器默认样式;标题页有灰烬/火星粒子。
- [ ] **动效与无障碍**:移动缓动不匀速、切换不瞬切、光圈连续插值;`prefers-reduced-motion` 下关装饰留机制。
- [ ] **数据**:最佳成绩刷新后仍在(localStorage);运行态不持久、刷新即新局。
- [ ] **开发者亲自玩通**:从头玩到熄灭再开一局,确认无死局、无卡顿、结算正确。
