# 知识横版闯关 spec.gameplay

## 1. 玩法结构名称

**知识横版平台闯关 / 章节式问答冒险**

本产品是一个可由任意 `skills/内容文件` 填充的横屏知识闯关游戏。最终用户打开的是已经填充完成的游戏：每个知识章节对应一关，玩家操纵角色在横版地图中移动、冲刺和攻击，接触题目触发物后进入答题，答对推进路线，答错扣生命。每关约 10 道混合题，答对率达到 50% 即可通关，并按答对比例获得 1-3 星评价。

本玩法借用“横版平台跳跃闯关”的结构能力，但不得使用或暗示任何具体商业 IP 的角色、关卡、美术、音效或命名。

## 2. 输出模式和设计粒度

| 维度 | 方案 |
|------|------|
| 内部输出模式 | `fixed-content` |
| 设计粒度 | 可填充玩法框架 |
| 最终用户体验 | 打开已填充完成的知识闯关游戏，直接选择章节关卡并游玩 |
| 内容来源 | 任意学科 / 任意主题的 `skills/内容文件` |
| 目标用户 | 泛用学习者，不限定年龄段或学科 |
| 准确性模式 | `strict` |

## 3. 核心循环

```text
选择章节关卡
→ 进入横版地图
→ 操纵角色移动 / 跳跃 / 冲刺 / 攻击
→ 接触题目触发物
→ 进入题目弹窗或题目战斗态
→ 作答混合题型
→ 答对：题目触发物解除 / 道路开启 / 获得奖励反馈
→ 答错：扣生命并显示解析，可再次挑战或继续寻找其他题
→ 达到通关答对率或解锁终点门
→ 进入结算页，按答对比例给 1-3 星
→ 解锁下一章 / 回看错题 / 重玩刷星
```

## 4. 关卡与通关规则

### 章节结构

- 每个 `skills/内容文件` 中的章节、模块、主题单元或知识簇映射为一关。
- 每关默认放置约 10 个题目触发物。
- 关卡横向展开，包含平台、坡道、空隙、移动平台、敌人、NPC、宝箱、知识门、路障和终点旗 / 终点门。
- 关卡长度应服务题目分布，不得让移动时间过长而稀释学习节奏。

### 通关与三星

| 结果 | 条件 |
|------|------|
| 通关 | 本关题目答对率 ≥ 50% |
| 1 星 | 答对率 ≥ 50% |
| 2 星 | 答对率 ≥ 70% |
| 3 星 | 答对率 ≥ 90% |

- 如果玩家到达终点但答对率不足 50%，终点门保持关闭，提示还需要补答若干题。
- 每关允许玩家回到未完成题目触发物处补答。
- 答错扣生命；生命归零后本关失败，回到本关起点或最近检查点重新挑战。
- 答错必须展示简明解析，解析内容必须来自内容文件或由可验证知识生成，不得乱编。

## 5. 玩家操作和核心动作

| 操作 | 作用 |
|------|------|
| 左右移动 | 控制角色在横版地图中前进、后退和调整位置 |
| 跳跃 | 跨越平台空隙、到达高处题目触发物或躲避敌人 |
| 冲刺 | 快速穿过安全路段、越过较远距离、触发速度挑战 |
| 攻击 | 击退普通敌人、打破轻型障碍、触发可攻击题目容器 |
| 接触 / 碰撞 | 碰到问号砖块、卷轴、宝箱、NPC、知识门、路障等后触发题目 |

实现时可支持键盘和触屏两套输入：桌面端使用方向键 / WASD + 空格 / Shift / J，移动端使用横屏虚拟按钮。触屏 UI 必须稳定占位，不遮挡题目弹窗和关键平台。

## 6. 题目触发物与题型

### 题目触发物

题目触发物可以混合使用，具体外观由主题风格和知识内容决定：

| 触发物 | 用途 |
|--------|------|
| 问号砖块 | 基础题，玩家跳起顶到或攻击后触发 |
| 漂浮卷轴 / 卡片 | 概念题或记忆题，接触后展开 |
| 知识门 | 关键题，答对后开门 |
| 宝箱 | 奖励题，答对获得生命、星星或护盾 |
| NPC | 情境题、解释题或多步骤问题 |
| 路障 / 封印 | 阻断路线的必答题 |
| 敌人弱点题 | 攻击敌人后触发答题，答对才真正击败 |

### 混合题型

最终 spec 应支持以下题型，由内容文件的知识特征自动选择：

- 选择题：适合概念辨析、定义、因果判断。
- 判断题：适合事实正误、规则边界。
- 填空题：适合关键词、公式、术语、时间、名称。
- 排序题：适合步骤、时间线、流程。
- 连线 / 拖拽匹配：适合对象关系、概念对应、因果链。
- 情境选择题：适合应用题、案例题、场景判断。

## 7. 内容槽位与 `skills` 映射

完整内容文件会与最终 spec 一起提供，通常位于项目根目录的 `skills/` 文件夹中。当前玩法方案按“任意知识内容”设计，后续实现必须读取每个内容文件全文，从中提取章节、知识点、题目、答案、解析和难度。

| 内容提取维度 | 映射到游戏模块 |
|--------------|----------------|
| 章节 / 模块 / 单元 | 关卡列表，每章一关 |
| 核心知识点 | 题目池、题目触发物、关卡主题标签 |
| 概念定义 | 选择题、判断题、填空题 |
| 过程 / 步骤 / 时间线 | 排序题、移动路线、阶段式机关 |
| 对象与关系 | 连线题、拖拽匹配题、NPC 问答 |
| 规则 / 公式 / 判断标准 | 关键知识门、路障题、终点门条件 |
| 常见误区 | 错误选项、答错反馈、复习提示 |
| 例子 / 案例 / 应用场景 | 情境题、NPC 对话题、宝箱奖励题 |
| 难度线索 | 题目星级、关卡前后段分布、敌人强度 |
| 视觉主题词 | 关卡背景色、地形装饰、粒子、封面图 prompt |

### 必须严格来自内容文件的内容

- 章节知识点。
- 题目文本。
- 答案。
- 解析。
- 题目难度。
- 知识归类。
- 题目与章节 / 模块的对应关系。

### 允许 AI 创作的内容

- 横版关卡地形布局。
- 题目触发物外观。
- 普通敌人样式。
- 道具外观和动画反馈。
- UI 主题化处理。
- 粒子、过场、奖励动画。
- 不影响知识事实的轻量关卡叙事。

## 8. 页面 / 状态粗结构

```text
构建期：读取 skills/内容文件 → 提取章节和题库 → 生成关卡数据 → 构建期生成封面图

运行时：
标题页
→ 章节选择页
→ 关卡准备页
→ 横版关卡主界面
→ 题目触发态 / 答题弹窗
→ 答题反馈态
→ 终点门 / 通关判定
→ 结算页
→ 错题回看 / 重玩 / 下一关
```

### 关键状态

- `level_locked`：章节未解锁。
- `level_ready`：章节可进入。
- `playing`：玩家正在横版地图中操控角色。
- `question_open`：题目弹窗打开，地图暂停或半暂停。
- `answer_correct`：答对反馈，触发物消失或变为已完成。
- `answer_wrong`：答错反馈，扣生命并展示解析。
- `life_zero`：生命归零，本关失败。
- `gate_unlocked`：答对率达到 50%，终点门开启。
- `level_complete`：结算，计算星级。
- `review_mode`：回看错题和解析。

## 9. 生图资产范围与时机

### 真实生图范围

本产品只需要 1 张真实 AI 位图资产：

| 资产 | 用途 | 时机 | required / optional |
|------|------|------|---------------------|
| 封面图 / 标题页主视觉 | 标题页背景或封面主图，用于建立知识冒险气质 | `build-time` | required for normal cover experience |

### 生图策略

- `IMAGE_GENERATION_TIMING = build-time`。
- 封面图必须在实现 / 构建阶段调用真实生图模型生成，不得用 CSS、SVG、Canvas、emoji 或文字占位伪装成生图。
- 构建期必须输出静态 `IMAGE_ASSET_MANIFEST`，至少包含封面图的 asset id、用途、required 标记、style prompt base、完整 prompt、negative prompt、比例、prompt hash、seed source、storage driver。
- 如果最终交付是单个 HTML 文件，封面图可在真实生成后以 base64 / data URL 或本地资产形式打包，并可作为首次写入 IndexedDB 的 `seed_source`。
- 游戏内角色、平台、敌人、题目触发物、UI、粒子和关卡背景不使用真实生图，全部由 SVG / Canvas / CSS / HTML 程序化实现。
- 如果构建期封面生成失败，不得宣称图片体验完成；最终产品可提供明确的无封面降级标题页，但失败资产必须保持 `failed / ready = false` 并保留重新生成入口或实现阶段重试说明。

## 10. 视觉方向

最终 spec 不固定单一画风，而是要求实现模型根据 `skills/内容文件` 的学科、主题和目标用户自动选择或混合视觉基底。候选方向包括：

| 视觉方向 | 适用内容 | 关键词 |
|----------|----------|--------|
| 像素冒险 | 泛用闯关、复古游戏感、低龄和全年龄 | pixel platformer, crisp pixel edges, bright readable palette |
| 校园冒险 | 课程学习、考试复习、错题闯关 | friendly campus adventure, clean classroom motifs, energetic UI |
| 百科博物馆 | 科普、地理、生物、历史、图鉴型知识 | museum exploration, labeled exhibits, natural history palette |
| 未来实验室 | 科学、数学、编程、工程 | sci-fi learning lab, holographic panels, neon accents |
| 纸片手账 | 语文、阅读、通识、轻学习 | paper craft, notebook stickers, warm hand-drawn interface |
| 奇幻知识大陆 | 混合学科、儿童向、故事化学习 | whimsical fantasy map, magical gates, glowing knowledge tokens |
| 清爽信息图 | 成人学习、职业知识、效率工具型内容 | flat vector infographic, calm UI, precise icons |

封面图的 `STYLE_PROMPT_BASE` 可从以上方向中选择，并加入具体学科主题。关卡内视觉必须与封面气质保持统一，但核心关卡对象仍以程序化绘制为准。

## 11. 高精度 SVG / Canvas / CSS 指南范围

本产品需要高精度横版关卡实现指南。最终 spec 必须包含绘制手册级内容，至少覆盖以下对象和机制：

### 可视化原语

- 玩家角色：SVG 或 Canvas sprite，具备 idle、run、jump、dash、attack、hurt、dead 状态。
- 平台地形：SVG path / rect / polygon 绘制，支持边缘高光、危险边界、可站立面标记。
- 移动平台：Canvas 或 DOM/SVG 混合，路径可视化，运动应连续插值。
- 题目触发物：问号砖块、卷轴、知识门、宝箱、NPC、路障、敌人弱点题。
- 敌人：几何或主题化角色，具备巡逻、受击、击退、消失动画。
- 攻击判定：短暂弧形 slash、冲击波或碰撞盒可视化调试规则。
- 碰撞反馈：落地尘埃、撞砖火花、受伤闪烁、开门光效。
- HUD：生命、答对数、答错数、答对率、星级进度、当前章节。
- 答题弹窗：题型自适应布局，题目、选项、拖拽区、解析区和确认按钮不能遮挡或溢出。

### 物理和碰撞规则

- 横版重力、跳跃抛物线、最大下落速度、冲刺速度、攻击硬直、敌人击退必须有明确参数。
- 碰撞盒必须与视觉外观基本一致，不能出现“看起来没碰到却触发”或“明明踩上去却掉落”的体验。
- 题目触发物接触后应冻结或半冻结关卡状态，防止玩家在答题时被敌人或陷阱继续伤害。
- `prefers-reduced-motion` 下关闭装饰粒子和夸张转场，但保留核心移动、碰撞、答题反馈。

### 最终 spec 必须增加的专项验收

- 核心关卡不是静态图片或纯文字问答页。
- 角色移动、跳跃、冲刺、攻击均有动画和即时反馈。
- 题目触发物具备不同外观、状态和完成反馈。
- 平台碰撞稳定，移动平台和边界不产生穿模。
- 答题弹窗在横屏桌面、平板和移动端都不遮挡关键 UI。
- 生命扣除、终点门开启、星级结算有明确视觉状态。
- 所有可视化对象有 hover / active / selected / disabled / correct / incorrect 等状态规则。

## 12. 准确性模式

`strict`

- 题目、答案、解析、知识归类和难度必须来自完整内容文件，或来自内容文件指向的可验证知识。
- 不允许为了关卡戏剧性改写知识结论。
- 错误选项应来自常见误区、相近概念或内容文件中的易混点，不得随机编造。
- 如果内容文件缺少答案或解析，构建阶段必须补充可验证解析，并在数据中标记来源。
- 验收时必须检查每道题是否能追溯到内容文件原文或可验证知识依据。
