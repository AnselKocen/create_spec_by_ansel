# 任意书多邻国学习 spec.gameplay

## 玩法结构名称

任意书多邻国式互动学习 app：把上游管线中用户上传的一本书，转化为一个已填充完成的轻量章节学习产品。最终用户打开后直接学习这本书，不看到上传、解析、选择参数或生成流程。

本产品借鉴多邻国的阶段式推进、即时反馈、路径地图和通关分享体验，但不照搬多邻国机制。核心目标是让“读不下 / 没耐心”的用户通过轻量互动真正掌握本书内容，完成后能自然地说“我懂这本书了”，并愿意分享给朋友。

## 输出模式和设计粒度

| 项目 | 方案 |
|------|------|
| 输出模式 | `fixed-content` |
| 设计粒度 | 可填充玩法框架 |
| 最终用户体验 | 打开某一本书已经生成好的学习 app，直接开始章节学习 |
| 上游 / 填充阶段 | 上传书、解析全文、切分章节、生成互动题、绑定原文 anchor、生成图片资产计划 |
| 最终 app 内不得出现 | 上传文件、输入书籍、选择生成参数、点击生成产品等工具流程 |

## 内容文件契约

后续最终 `spec.md` 必须按以下内容文件结构写入“涉及的 SKILL / 内容文件清单”：

| 内容文件路径 | 覆盖模块 | 在本产品中的用途 |
|-------------|----------|------------------|
| `skills/{{BOOK_ID}}/full-text.md` | 全书结构化正文 | 章节切分、核心概念抽取、题面生成、标准答案、错答反馈、金句来源 |
| `skills/{{BOOK_ID}}/toc.json` | 全书目录 | 章节脉络拖拽的标准顺序、章节重组和章节标题来源 |
| `skills/{{BOOK_ID}}/anchor-index.json` | 段落级原文锚点索引 | 所有题目、反馈、引用、金句、综合关评分依据的可追溯 anchor |
| `skills/{{BOOK_ID}}/metadata.json` | 书名、作者、题材、目标读者、估时等元信息 | 视觉风格、吉祥物、章节数量、互动组合和学习节奏推导 |

对错标准的唯一权威是本书自身。所有正确答案、错误反馈、真伪辨别、反向考核、应用题评分依据、章节综合关评价和通关金句，都必须能追溯到 `full-text.md` 中的原文段落，并绑定 `anchor-index.json` 的有效 anchor。

## 核心循环

```text
打开 app
→ 检查真实图片资产缓存
→ cache hit：读取 IndexedDB Blob 并解码
→ cache miss：进入主题化资产准备页，生成缺失图片并写入 IndexedDB
→ required 图片 ready 后进入正常图片体验标题页
→ 若图片失败 / 超时 / 用户取消：可跳过进入明确的 no-image 兜底体验
→ 选择 / 继续当前学习进度
→ 章节路径地图
→ 进入当前章
→ 轻量互动 4-6 个
→ 章节综合应用 1 个
→ 章末总结：核心概念、原文金句、关系图、下一章解锁
→ 重复 5-7 章
→ 全书通关报告卡 + 分享卡
```

## 章节结构和内容规模

| 模块 | 默认范围 |
|------|----------|
| 章节数 | 5-7 章，由书的目录、论证递进、叙事阶段或主题聚类决定 |
| 每章核心概念 | 3-7 个 |
| 每章互动数量 | 4-6 个 |
| 每章综合应用 | 1 个 |
| 每章互动类型组合 | 从 6 种候选互动中挑 2-3 种搭配，不要求 6 种都出现 |
| 全书通关产物 | 学习战绩、掌握概念数、章节高光、原文金句、分享卡 |

章节应尽量保留本书自身结构。若原书章节过多，可以聚合为 5-7 个学习单元；若原书章节过少，可以按主题、论证链、故事阶段或方法模块拆分，但每个学习单元都必须有原文依据。

## 6 种互动候选菜单

最终 spec 必须把互动机制限制在以下 6 种菜单内。填充阶段只能根据章节内容挑选、组合和改写题面，不允许新增菜单外的核心互动类型。

| 互动类型 | 玩家做什么 | 标准答案来源 | 适用章节 |
|----------|------------|--------------|----------|
| 概念排序 | 拖拽核心概念，排成本书逻辑顺序、因果顺序或方法步骤 | 书中论证顺序、定义依赖、方法步骤 anchor | 概念密集、方法论、理论递进章节 |
| 复述测试 | 用自己的话复述一段核心观点，AI 比对原文并高亮遗漏、误解和准确部分 | 原文段落、关键术语、必要条件 anchor | 关键概念、核心论断、章节总结 |
| 应用题 | 在场景中回答如何使用书中观点、方法或判断标准 | 书中案例、原则、判断标准 anchor | 商业、自助、哲学、科普、方法型章节 |
| 反向考核 | 看到一个错误论断，引用或选择原文来反驳 | 书中明确相反观点、限定条件或定义 anchor | 容易误读、观点锋利、反常识章节 |
| 章节脉络拖拽 | 将打乱的章节标题、段落标题或论证步骤拖回正确顺序 | `toc.json` + 原文结构 anchor | 章节开头、章末复盘、全书结构回顾 |
| 真伪辨别 | 在“书里观点”和“GPT 编的相似但错的观点”中二选一 | 正确项来自原文，错误项来自相似误读但不得凭外部知识判断 | 定义、结论、金句、论证转折 |

## 互动组合规则

每章选择 2-3 种互动类型，形成轻量但有变化的学习节奏：

| 章节特征 | 推荐组合 |
|----------|----------|
| 概念 / 术语密集 | 概念排序 + 真伪辨别 + 复述测试 |
| 论证 / 推理密集 | 章节脉络拖拽 + 反向考核 + 真伪辨别 |
| 方法 / 实践导向 | 应用题 + 概念排序 + 复述测试 |
| 文学 / 叙事类 | 章节脉络拖拽 + 复述测试 + 应用题 |
| 哲学 / 思辨类 | 反向考核 + 真伪辨别 + 复述测试 |
| 商业 / 自助类 | 应用题 + 反向考核 + 概念排序 |

每章不应机械凑满题型。互动选择必须服务本章学习目标：先让用户抓结构，再理解关键观点，最后能用自己的话或现实场景应用。

## 内容提取维度与玩法映射

| 提取维度 | 从书中提取什么 | 映射到产品模块 |
|----------|----------------|----------------|
| 对象 / 概念 | 核心术语、人物、案例、工具、关键名词 | `key_concepts`、概念排序、概念关系图 |
| 过程 / 结构 | 目录顺序、论证路径、叙事阶段、方法步骤 | `chapters`、章节脉络拖拽、章节路径地图 |
| 规则 / 论断 | 判断标准、主张、原则、结论、限制条件 | 真伪辨别、反向考核、应用题标准答案 |
| 关系 | 因果、层级、对立、依赖、递进 | 概念关系图、应用题场景、章末总结 |
| 冲突 / 误解 | 常见误读、相似但错误的说法、概念混淆 | 错误项、错答反馈、反向考核题面 |
| 感受 / 气质 | 书的题材、情绪、媒介感、时代感 | UI 风格、吉祥物、粒子、生图提示词 |
| 可验证内容 | 原文段落、定义、引用、目录、案例 | `source_anchor`、评分依据、验收追溯 |
| 可应用内容 | 方法、框架、可迁移洞见、实践步骤 | 章节综合应用、通关报告中的“我学会了什么” |

## 反馈和对错机制

对错反馈要轻量、阶段性、可复盘，不做高压考试。

| 场景 | 反馈规则 |
|------|----------|
| 答对 | 点亮选项 / 拖拽项，显示简短正反馈和对应原文 anchor，可进入下一题 |
| 答错 | 显示温和错误反馈，引用或展开原文 anchor，允许重答或继续复习 |
| 复述测试 | AI 高亮“准确复述 / 缺失关键点 / 误解原意”，反馈必须绑定原文段落 |
| 反向考核 | 用户引用或选择的原文必须能反驳错误论断；反馈解释为什么该 anchor 有效或不够 |
| 真伪辨别 | 错误项必须是“相似但错”的书内误读，不得靠外部知识或文字陷阱制造难度 |
| 章节综合关 | 开放性评估，不把用户卡死；反馈指出掌握点、缺口和可回看原文 |

反两极分化设计应参考 anything2mbti 的精神：题目不要让用户一眼看穿“正确答案长什么样”。错误论断应来自真实可能的误解，两个选项在表面上都应像合理说法，最终通过本书原文 anchor 判定。

## 生图资产范围和时机

本产品需要真实位图资产，默认使用：

```text
IMAGE_GENERATION_TIMING = first-run-cache
```

必需资产：

| 图片类型 | 数量 | 用途 | 必需 |
|----------|------|------|------|
| 标题页书封意象图 | 1 张 / 书 | 首屏氛围和书籍主题信号 | 是 |
| 书籍主题吉祥物 | 1 张 / 书 | 反馈、引导、通关陪伴 | 是 |

可选资产：

| 图片类型 | 用途 |
|----------|------|
| 通关庆祝 CG | 全书完成时的情绪高潮 |

不再为每章生成章节插图，不生成分享卡背景图，也不生成概念意象图。章节入口、章末回顾、概念关系图和分享卡背景全部由 HTML / SVG / CSS 主题化实现，不登记为真实生图资产。

默认不设置 `build-time` 例外。最终 app 首次启动时先检查 IndexedDB；cache hit 只读取 Blob 并解码，不调用生图；cache miss 进入资产准备页，一起生成缺失的封面图、吉祥物和通关庆祝 CG 并写入 IndexedDB。封面图和吉祥物是进入正常图片体验前的 required 图片；通关庆祝 CG 是 optional 图片，失败不阻塞学习主流程。任意 required 或 optional 图片失败、超时或用户取消时，都允许用户跳过资产准备页进入明确的 no-image 兜底体验；失败资产保持 failed / ready=false，并保留重试入口。

## 视觉方向

视觉不锁死“多邻国绿”。它应由书的题材、气质和目标用户推导：

- 学术 / 科普：知识图鉴、清晰标注、克制但有成就感。
- 哲学 / 历史 / 经典：复古手稿、档案、纸张、墨迹或印章感。
- 商业 / 管理 / 自助：现代数据卡、进度仪表、干净明快的目标感。
- 文学 / 小说 / 童话：绘本、手绘、胶片、叙事插画或柔和分镜。
- 科技 / 未来：赛博、全息、代码雨、深色但保持阅读清晰。
- 中国传统 / 武侠 / 古典：国潮、工笔、卷轴、纹样和印章。

多邻国式参考主要落在交互节奏和反馈：路径节点、章节解锁、即时正误、轻量庆祝、吉祥物陪伴、通关报告和分享卡。视觉风格必须随书变化，不能所有书都生成同一个绿色卡通界面。

## SVG / CSS 可视化要求

最终 spec 应包含专项 SVG/CSS 指南，但重点不是物理 / 化学级模拟，而是学习产品的结构可视化：

| 可视化对象 | 推荐技术 | 必须写清 |
|------------|----------|----------|
| 章节路径地图 | SVG path + 节点组件 | 已完成 / 当前 / 锁定状态、路径点亮、移动端布局 |
| 章节进度环 | SVG circle + `stroke-dasharray` | 本章进度、全书进度、状态颜色 |
| 概念关系图 | SVG nodes + edges | 因果、对立、层级、依赖关系编码，节点 hover 展开原文 anchor |
| 答对 / 答错反馈 | SVG icon + CSS 动效 | 勾、提示、脉冲、错答警示，不破坏原始内容颜色语义 |
| 分享卡 | HTML/CSS/SVG 叠加 | 书名、掌握概念数、金句、战绩、背景图叠加规则 |

概念关系图是章末核心可视化，最终 spec 需要写出节点、连线、图例、标注、交互态和常见画错点，避免变成“几个词随便连线”的装饰图。

## 准确性模式

准确性模式：`semi-strict`。

要求：

- 从书中提取的核心概念、论断、目录、引用、案例和标准答案必须准确。
- 对错标准仅限本书自身，不引入外部权威、百科、其他书或模型常识。
- 应用题场景、反向考核措辞、吉祥物反馈、章节过渡文案可以剧本化，但评分依据必须回到本书 anchor。
- 当书中观点本身与外部事实冲突时，本产品只判断“是否符合本书说法”，不替本书做外部事实裁判。
- 如果原文不足以支持某道题或反馈，必须删题、降级为开放讨论，或要求补充内容，不得臆造标准答案。

## 已确认点

1. 难度模式（轻松 / 标准 / 高挑战）保留为 P1，不作为 P0 必需。
2. 通关分享卡支持导出图片即可，PNG / JPG 均可，不强制单一格式。
3. 产品包含资产准备页；只生成标题页书封意象图、书籍主题吉祥物和通关庆祝 CG。必需图只阻塞正常图片体验，不阻塞进入产品；任意图片失败、超时或用户取消时都可跳过进入 no-image 兜底体验，并保留错误状态和重试入口。
